# Emotion-Paint システム設計・機材連携 完全仕様書

---

## 1. システム全体概要
- **システム名称**: Emotion-Paint（デジタル陶芸体験・リアルタイム3D UVペイントシステム）
- **コンセプト**: 「2台の端末でお客さんが陶芸体験をする展示・会場インスタレーション」
- **体験の流れ**:
  1. お客さんが手元のタブレットで壺に絵を描き、感情エフェクトや形状を選ぶ。
  2. お客さんの正面にある**縦型モニター**の3D壺に、手元の絵がリアルタイムで立体反映される。
  3. 完成ボタンを押すと、手元タブレットで作者サインを描画。サイン画像データを添付した `save` イベントが**縦型モニター**へ送信され、**縦型モニター**側で壺の4方向写真が高画質キャプチャされる。
  4. **縦型モニター**が撮影した4方向写真と、タブレットから届いたサイン画像が Firebase Storage にアップロードされ、その公開URLを使って Google Cloud Run 経由で公式 Instagram にカルーセル自動投稿される。
  5. 投稿完了後、**手元のタブレット画面に Instagram公式アカウントの QRコードがポップアップ表示**される。お客さんは自分のスマホで手元のQRコードを読み取って、たった今投稿された自分の作品を Instagram 上で閲覧・保存・シェアする。

## 2. システム基本5要素の定義

### ① 入力 (Input)
- **手元タブレット（iPad等）のタッチ & スタイラスペン入力**:
  - 描画ストローク（HTML5 Canvas上の筆圧・描画）
- **感情パラメータ入力（5種類）**:
  - `joy` (たのしい 🌟) / `shock` (おどろき ⚡) / `sad` (せつない 💧) / `confuse` (こんらん 🌀) / `fire` (しげきてき 🔥)
- **造形・演出選択**:
  - 壺の形状切り替え（vaseShape: vase01, vase02など）
  - 背景テーマ選択（background01〜07）
- **完成トリガー・署名**:
  - 作者の手書きサイン描画（サインオーバーレイ）
  - 保存（Save）実行トリガー

### ② 処理 (Processing)
- **手元端末側処理（タブレット）**:
  - HTML5 Canvas（480×480px）上でUVテクスチャをリアルタイム生成。
  - 描画のたびに、キャンバス全体の画像データ（PNG DataURL）を `draw` イベントでサーバー経由で**縦型モニター**へ送信。
  - サイン描画後、サイン画像を付与した `save` イベントを送信。
  - **縦型モニター**から `saveComplete` 受信後、画面上に Instagram 公式リンクの QRコードを生成・ポップアップ表示。
- **縦型モニター側処理（縦型モニター ＋ PC）**:
  - 手元から届いた画像テクスチャを Three.js のマテリアルに即時反映し、3D壺を動的回転描画。法線・凹凸マップを再計算。
  - `save` 受信時に一意な作品ID（`workId`）を発行。
  - 壺を回転させながら4方向アングル（正面・右・背面・左）を高画質レンダリング＆JPEGキャプチャ。
  - 4方向画像とサイン画像を Firebase Storage に直接アップロードし、公開URLを取得。
  - 取得した画像URLと作品データをシステム本体へ `POST /api/works/:id` で送信。
  - 完了後、手元タブレットへ `socket.emit('saveComplete')` を送信。
- **サーバー側処理（システム本体: server.js / Google Cloud Run）**:
  - Socket.io による超低遅延な双方向データ中継（ブロードキャスト）。
  - ルートアクセス (`/`) を `/?role=viewer` に自動リダイレクトするルーティング制御。
  - `POST /api/works/:id` 受信時に、サーバー内部の非同期バックグラウンド処理として `POST /api/instagram/carousel` を呼び出し、Instagram Graph API 経由でカルーセル自動投稿を実行。

### ③ 出力 (Output)
- **縦型モニター（Viewer画面）**:
  - URL: `/?role=viewer`
  - 3D壺の動的回転表示、リアルタイムペイント映像（大迫力の鑑賞専用スクリーン）。
- **手元タブレット（Controller画面）**:
  - URL: `/?role=controller`
  - お絵描きキャンバスUI、筆設定、感情エフェクトスライダー。
  - **完成時: Instagram公式アカウント（@atelier_kanna1212）へ誘導する QRコードのポップアップ表示。**
- **SNS発信 ＆ 来場者スマホ（Instagram）**:
  - Instagram Graph API による4面画像＋サイン入りカルーセル自動投稿。
  - 感情%の自動キャプション生成（例: 🌟 たのしい 60% / 🔥 しげきてき 40%）。
  - **来場者は手元タブレットのQRコードをスマホで読み取り、公式Instagram上で自分の作品を直接閲覧・保存・いいね！する。**

### ④ ネットワーク (Network)
- **会場内ローカルLAN**:
  - 会場用 Wi-Fi ルーター（電波干渉を防ぐため **5GHz帯 / Wi-Fi 6** 推奨）。
  - 縦型モニター用PCは有線LAN接続（または5GHz Wi-Fi）、手元タブレットは5GHz Wi-Fi接続。
- **通信プロトコル**:
  - **WebSocket (Socket.io)**: 手元描画テクスチャ（PNG DataURL）と感情パラメータの超低遅延双方向ストリーミング。
  - **HTTPS (REST API)**: 作品データの保存 (`POST /api/works/:id`)、Firebase Storage アップロード、Instagram Graph API 連携。
- **クラウドインフラ通信**:
  - Google Cloud Run、Firebase Storage、Meta Graph API へのインターネット常時接続。

### ⑤ 電源 (Power)
- **商用電源 (AC 100V)**:
  - 縦型モニター、駆動用PC、会場用Wi-Fiルーター（コンセントから常時給電）。
- **USB-PD 急速給電**:
  - 手元タブレット（体験中の電池切れ、画面の自動スリープや画面減光を防ぐため、USB-Cケーブルで常時給電）。
- **保護設備（推奨）**:
  - 瞬時電圧低下（瞬低）やコンセント抜けによる展示中断を防ぐ小型UPS（無停電電源装置）。

### ② 2系統のイベント送信パス（`draw` と `emotion` の論理的分離）
25種類のツールはすべて単一のイベントで送られているわけではなく、ツールの性質に応じて**2つの異なるSocket.ioイベントパス**に明確に分離されています。

| ツール分類 | 対象ツール | 使用イベント | 送信データ形式 | 縦型モニターでの反映内容 |
| :--- | :--- | :---: | :--- | :--- |
| **ペン系（15種）** | ポコポコ、キラキラ、ドロドロ、ピリピリ、バリバリ、バキバキ、シトシト、ボヤー、スウー、グルグル、アベコベ、グニャリ、シュッ、ピカピカ、キリリ | **`draw`** | Base64 PNG画像データURL (`dataURL`) | 3D壺表面のテクスチャ（CanvasTexture）更新、ハイトマップ・法線マップ再計算 |
| **エフェクト系（10種）** | トローリ、フワフワ、ガタガタ、ピカッ、ギザギザ、ドップリ、ウネウネ、カクカク、ヌルリ、ツブツブ | **`emotion`** | 各エフェクトの強度値（0.0〜1.0）を格納したJSONオブジェクト (`effectValues`) | Three.js のカスタムシェーダーUniform変数への即時バインド（頂点波打ち・走査線ノイズ・環境光） |

#### 分離の論理的理由
1. **通信パフォーマンスの最適化（60fpsの滑らかな操作性）**:
   - スライダーを指で素早く動かした際、毎回重い画像（Base64 PNG）を生成・転送すると通信帯域を圧迫し遅延の原因になります。数値だけの軽量なJSON（`emotion`）として送信することで、遅延ゼロの滑らかなリアルタイム・シェーダー演出を実現しています。
2. **責務の分離（静的テクスチャ vs 動的空間演出）**:
   - `draw` は陶器の表面に焼き付けられる「静的な絵柄・テクスチャ」を更新します。
   - `emotion` は壺そのものを動的に波打たせたり、会場のライティング色を変化させたりする「動的な感情・シェーダー演出」を制御します。

### ③ 感情推測の論理構成と計算アルゴリズム
体験者が描画・装飾を行う中で使用したツールの実績（特にエフェクトスライダーの適用度合い）から、体験者の感情状態を数値的に推定・分析します。

#### 1. 入力データ
- `effectValues`: 各エフェクトツールの適用度合い（0.0 〜 1.0）を保持するキー・バリューオブジェクト。
  - 例: `{ melt: 0.8, wobble: 0.5, pop: 0, ... }`

#### 2. 計算ロジック（calcEmotionFromEffects）
1. **感情別合計値の集計**:
   5つの各感情カテゴリについて、属するエフェクトツールの適用値を加算。
   $$\text{Totals}[\text{emotion}] = \sum_{t \in \text{TOOLS}_{\text{emotion}}} \text{effectValues}[t.\text{id}]$$
2. **全体比率への正規化（パーセンテージ化）**:
   5感情の総和 $S = \sum \text{Totals}$ を算出。
   - $S > 0$ の場合: 各感情の割合 $\text{EmotionPct}[\text{emotion}] = \frac{\text{Totals}[\text{emotion}]}{S}$
   - $S = 0$（何もエフェクトが使われていない場合）: 均等配分（各感情 20% / 0.2）
3. **支配的感情の特定（getDominantEmotion）**:
   割合が最も高い感情を「支配的感情（Dominant Emotion）」として特定。

#### 3. 推測結果の活用先
1. **手元タブレット**:
   - 焼き上げ（保存）完了時、手元のQRコード画面に「感情分析バー（Emotion Bar）」として各感情の内訳（例: 🌟 楽しい 60% / 🔥 しげきてき 40%）をグラフィカルに表示。
2. **縦型モニター**:
   - 決定された支配的感情に応じて、3D壺の背景光やライティング色（環境光）がリアルタイムに呼応。
3. **Instagram自動投稿**:
   - カルーセル投稿のキャプション本文に、推測された感情比率（例: 「🌟 楽しい 70% / ⚡ おどろき 30%」）とハッシュタグ（`#感情アート` など）を自動挿入。

## 6. Canvas（480×480px）によるUVテクスチャ生成と3D壺マッピングの論理構成・仕組み

手元タブレットの2Dキャンバスに描かれた筆跡が、正面の縦型モニターの立体的な3D壺にリアルタイムで美しく、歪みなく立体マッピングされる内部アーキテクチャの論理構成です。

### ① 2DキャンバスでのUVテクスチャ生成
- **正方形解像度（480×480px）とUV空間の対応**:
  - 手元タブレットの描画エリアは $480 \times 480\ \text{px}$ の正方形 HTML5 Canvas（`canvas`）を採用。
  - テクスチャUV座標系（$U \in [0.0, 1.0]$、$V \in [0.0, 1.0]$）と線形に $1:1$ で対応しており、水平方向 $X$ が円周方向 $U$、垂直方向 $Y$ が高さ方向 $V$ に対応します。
- **背景画と描画レイヤーの合成**:
  - 来場者が選択した背景テーマ画像（`background01.jpg` 等）が下地として描画され、その上に来場者のオノマトペペンによるストロークや流体シミュレーション（Lava）、パーティクルがリアルタイムに重畳されます。
- **復元型消しゴム（Smart Eraser）**:
  - 単なる白色の上塗り消去ではなく、初期背景のピクセルデータ（`bgImageData`）をメモリに保持。消しゴム操作時に該当箇所のピクセルデータをサンプリング復元することで、下地背景を傷つけずに描いた絵だけを元に戻す非破壊的な消去処理を実装しています。

### ② 3D壺ジオメトリの構築と「累積弧長UVマッピング」

#### 1. 回転体ジオメトリ（LatheGeometry）の生成
- 壺の断面形状データ（制御点：半径 $r$、高さ $h$）から `THREE.SplineCurve` を生成。
- 外壁面、口の縁（リップ）、肉厚（`WALL_THICKNESS = 0.08`）を持たせた内壁面、底面中心を繋ぐ完全な断面プロファイルを構築。
- Y軸を中心軸として360度（`LATHE_SEGMENTS = 64` 分割）回転させることで、厚みのある中空陶器メッシュ（`THREE.LatheGeometry`）を動的生成します。

#### 2. 円筒UVマッピング（U座標：円周方向）
- 円周方向のセグメント番号から線形に正規化：
  $$U = \frac{\text{seg}}{\text{LATHE_SEGMENTS}} \quad (0.0 \le U \le 1.0)$$
- キャンバスの横軸（$X: 0 \to 480$）が、3D壺の周囲360度（$0^\circ \to 360^\circ$）にシームレスに一周巻き付きます。

#### 3. 累積弧長マッピング（V座標：高さ方向の歪み防止アルゴリズム）
- **技術的課題**:
  - 単純に頂点の高さ座標（$Y$）から線形に $V$ を割り振ると、壺の「くびれ」や「ふくらみ」などの傾斜の急な曲面部分で、テクスチャが縦方向に引き伸ばされて激しい歪み（テクスチャストレッチ）が生じます。
- **解決アルゴリズム（累積弧長法: Cumulative Arc Length）**:
  - 断面スプライン曲線に沿った微小線分の長さ（弧長）を積分・算出：
    $$\Delta L_i = \sqrt{(r_i - r_{i-1})^2 + (h_i - h_{i-1})^2}$$
    $$\text{ArcLength}_i = \sum_{k=1}^i \Delta L_k, \quad \text{TotalLength} = \sum_{k=1}^N \Delta L_k$$
    $$V_i = \frac{\text{ArcLength}_i}{\text{TotalLength}} \quad (0.0 \le V \le 1.0)$$
- **効果**:
  - 壺のカーブの傾斜や曲率に関わらず、陶器の表面距離に対して均一なピクセル密度でテクスチャがマッピングされるため、描いた絵のプロポーションが一切崩れず、真円や繊細な筆跡がそのまま陶器表面に美しく展開されます。
- **内壁・底面の処理**:
  - 内壁面は外壁面のUV座標を反転・折り返してマッピングし、壺の内側を上から覗き込んだ際も自然な陶器の風合いを維持。
  - 壺の底面裏側にも底面ディスク（Bottom Disc）を配置し、持ち上げて底を見た際にも描画が施されている体験を提供します。

### ③ リアルタイム通信とプロシージャル凹凸生成（陶器マテリアル）

#### 1. WebSocket による超低遅延同期
- 手元タブレットで1画描くたびに、CanvasデータがPNG形式のDataURLとして `socket.emit('draw', { dataURL, mode, vaseShape })` で送信されます。
- 縦型モニターがこれを受信し、内部のテクスチャキャンバス（`texCanvas`）へ転送。`THREE.CanvasTexture.needsUpdate = true` を発火してマテリアルを瞬時に更新します。

#### 2. プロシージャル凹凸生成（ハイトマップ & 法線マップの動的構築）
2Dの絵を単なる平面プリントとして貼り付けるのではなく、**「釉薬（ゆうやく）の盛り上がり」「陶器に彫り込んだような立体感」**を表現するため、Canvas画像からリアルタイムに2種類のマップを生成します：

1. **変位/ハイトマップの自動生成（`buildHeightMap`）**:
   - ピクセルごとの輝度（Luminance: $Y = 0.299R + 0.587G + 0.114B$）を計算。
   - 濃い色（インクを塗った部分）ほど反転して「高低差」とし、Three.js の `displacementMap` として3D頂点を物理的に盛り上げ/彫り込みます。
2. **法線マップの自動生成（`buildNormalMap`）**:
   - 上下左右の隣接ピクセルとの輝度差から局所的な勾配（傾斜ベクトル $dx, dy, dz$）をSobelフィルタ的に計算。
   - 傾斜の向きをRGB（法線ベクトル）にエンコードして `normalTexture` をリアルタイム生成。
   - 光の反射や陰影がリアルタイムに凹凸に合わせて変化し、陶器に彫刻を施したような陰影・反射を実現します。

#### 3. 物理ベース陶器マテリアル（PBR）
- `THREE.MeshStandardMaterial` を採用し、陶器特有のツヤと光沢（roughness: 0.25〜0.35, metalness: 0.05〜0.1）を物理ベースレンダリング（PBR）で再現します。

### ④ 壺のTOP（口・開口部）とEND（底面・接地部）の構造とテクスチャ処理

#### 1. 3Dジオメトリ（断面プロファイル）における構造
壺は1枚の薄皮ポリゴンではなく、**肉厚（`WALL_THICKNESS = 0.08`）を持った中空構造**として構築されています。
- **TOP（上端・口・開口部）**:
  - 外壁の最上部（`outerTop`）と内壁の最上部（`innerTop`）が、厚みを持った**「縁（リップ / リム）」**として滑らかに接続されています。
  - 上から見下ろした際にもポリゴンの裏抜け（透明化）が生じず、本物の陶器らしい「口の厚み」と「内側の空洞（奥行き）」がリアルに表現されます。
- **END（下端・底・接地部）**:
  - 外壁の底と内壁の底がそれぞれ中心線（$X=0$）で閉じており、陶器の高台・底面を形成しています。
  - さらに、壺を斜め下から見上げた際や回転した際にも底が不自然に見えないよう、**底面専用の円形ディスクメッシュ（`bottomDisc`: `CircleGeometry`）**が下向きに配置されています。

#### 2. UVテクスチャマッピングにおける対応関係
手元キャンバス（480×480px）の上下が、壺のTOPとENDに以下のように論理的に対応付けられます：
- **TOPへの対応（$V = 1.0$）**:
  - キャンバスの**一番上（$Y=0$）**が、3D壺の外側の口の縁（$V=1.0$）にピッタリ一致します。
  - 口の厚み（リップ）部分にもキャンバス上端の絵柄が自然に回り込みます。
- **ENDへの対応（$V = 0.0$）**:
  - キャンバスの**一番下（$Y=480$）**が、3D壺の外壁の底（$V=0.0$）に一致します。
- **内壁面への反転マッピング（ミラーリング）**:
  - 外壁面のUVマッピングが口の縁で折り返され、口（$V=1.0$）から内底（$V=0.0$）へ向かって**反転マッピング**されます。これにより、壺の内側を上から覗き込んだ際にも絵柄が自然に回り込んで見えます。
- **底面ディスク（Bottom Disc）**:
  - 壺の裏側（底板）にはキャンバステクスチャ全体が円形に丸く独立マッピングされ、底面を露出させたアングルでも絵柄が美しく確認できます。
